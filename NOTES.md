# R&D Pipeline — Working Notes

## Evaluation Metrics

Two independent layers:

### 1. Person-level (custom)
| Metric | Meaning |
|--------|---------|
| `accuracy_event` | `(1/N) * sum I(pred_i == gt_i)` — sequence-order accuracy |
| `identification_rate` | correctly identified persons / total GT persons |
| `missed` / `false_positives` | set-level person ID errors |

UNRECOGNIZED tracks contribute here via their best-match label — intentional.
The system detected the person in the right order even if below confidence threshold.

### 2. Track-level biometric (NIST FRVT / ISO 19795-1)
| Metric | Meaning |
|--------|---------|
| `TPIR(T)` | correct-identity tracks accepted at T / all genuine tracks |
| `FPIR(T)` | wrong-identity tracks accepted at T / all impostor tracks |
| `n_genuine_total` | total genuine track probes (>= n_gt persons) |
| `n_genuine_probes` | tracks correctly identified at T >= 0.5 |

Each track = one probe. UNRECOGNIZED tracks count toward denominator (honest miss).

### Key distinction
- `accuracy_event = 1.0` + `TPIR = 0.72` is NOT a contradiction.
  - 1.0 means: all 25 people detected in right order
  - 0.72 means: 18/25 tracks identified with sim >= 0.5

## engine.py — eval mode

In `eval: true` mode, production filters on UNRECOGNIZED tracks are bypassed
(`recognize_removed_tracks`, lines ~733-769). All tracks flow to results with `image=None`.
This is required for honest TPIR — otherwise unconfident tracks are silently dropped.

## ChokePoint Dataset Notes

- Sequential, non-overlapping windows: one person per frame range
- GT annotation: `{person_id: first_frame}` — ordered by appearance
- P1 portal: 25 persons per sequence
- In clean sequences (e.g. P1E_S1_C3): impostor=0, system never confidently misidentifies
